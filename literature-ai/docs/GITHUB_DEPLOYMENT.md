# GitHub 管理代码与发布

2026-10-09 用户要求：冻结当前版本，退役详情页机理与写作、中文译文、历史解析证据，后续代码与部署以 GitHub 为准。

代码仓库为 https://github.com/yuhaoli119119/AI-shujvku 。服务器 PostgreSQL 仍是业务数据真源，全部开发、测试、文件处理、部署与核验仍在服务器执行。

`freeze/current-20261009` 是一次性导入当前运行代码的冻结分支。后续修复从 GitHub 提交开发；不再把服务器运行目录的手工修改反向认作新版本。冻结分支保留当前版本，旧备份按用户逐项确认的清单删除。当前数据库冻结检查点只在服务器保存，不进入 Git。

## 发布操作

在服务器运行 `./update.sh plan <完整40位commit>`。脚本从固定 GitHub 仓库获取该提交，创建 `/opt/literature-ai/releases/<commit>` 干净检出，生成 `/opt/literature-ai/deploy-state/<commit>/plan.json`。分支名、脏检出、不同来源仓库都会被拒绝。项目 `.env`、密码文件、业务文件、数据库卷沿用服务器持久存储。

核对计划中的 commit、六个应用/网关服务与代码挂载路径后，以返回的计划摘要执行 `./update.sh apply <commit> --plan-sha256 <摘要>`。涉及服务重建的操作先按 AGENTS.md 获取本次具体授权。构建上下文、后端、前端、提示词与网关配置均来自 GitHub 检出；容器中的代码挂载为只读。PostgreSQL、Redis、MinIO、Grobid 不在重建清单中。脚本不删除历史备份、数据库记录或旧源码副本。

`./update.sh verify <commit>` 核对容器版本标签、代码挂载与后端 `/api/health` 的 `git_commit`。发布成功才写 `DEPLOYED_GITHUB_COMMIT` 和发布回执。实际域名仍须核对详情页、原文图片、当前提取数据与图片解读；启动成功与 HTTP 200 不能代替页面验收。

失败时保留失败状态与回执，不宣称已经发布。代码回退使用 GitHub 上另一个明确提交重新 plan/apply；不能用未经版本管理的服务器目录或旧备份作为代码来源。数据库删除与恢复单独执行，代码回退不会恢复被删除的数据。

## 本次退役的边界

删除详情页三个旧区域及其专用翻译、历史论断展示、机理与写作提取实现和提示词；停止读取对应旧数据。删除清单中的机理论断、写作卡及其证据片段/定位记录另行经确认删除。

旧证据侧栏主要由已有 DFT/性能等记录临时投影，不是一张独立证据表。移除该投影接口，不据此删除现行 DFT、性能、图表、PDF 或 rebuild 数据/来源。共享数据库 ORM 和通用证据定位定义仍供保留数据使用，不在本次整表删除范围。当前已有中文标题/摘要属于元数据，与本次删除的译文预览功能分别处理。
