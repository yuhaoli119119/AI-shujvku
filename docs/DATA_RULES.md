# 数据规则：精度、分行、溯源、去重、冲突、分析

适用于 `PIPELINE_TARGET.md` 第二～四步产生的全部图表数据与实验/DFT 数据。
**这些规则约束的是现行目标流程；数据库、分析和导出只使用新 AI 提取流程的数据。旧提取数据退役，备份仅用于恢复。**

## 1. 数值与精度

1. **保留原始精度**：原文/图表写几位就记几位，不做四舍五入"美化"。
2. 单位保留原文单位，同时记录其含义（如 eV、eV/atom、mA cm⁻²、mV vs RHE）。不做自动换算覆盖，需要换算时另存换算值并写明依据。
3. **估读**：只有从图上读出的值才允许估算，且
   - 最多保留 **两位小数**；
   - 必须标记为"估读"，并注明**估读不是精度承诺**（不代表原文对该位有效）；
   - 同时记录估读依据（哪张图、哪个坐标、怎么读的）。
4. **模糊/看不清 = 留空**：不要写 0、写"约"、写范围中值来充数。留空并在备注里写清缺什么。
5. 缺失 ≠ 0；未测量 ≠ 未检出。语义不同的空缺要分开表述。

## 2. 分行规则

以下任一不同，就必须**分行记录**，不得合并成一行：

- 材料 / 催化剂身份
- 构型（如单原子 vs 双原子、具体几何构型）
- 活性位点
- 反应步骤 / 吸附物 / 中间体
- 实验或计算条件（温度、电位、pH、电解液、泛函、截断能、k 点等）
- 数据类型（实验 vs DFT）

同一行只允许承载一组自洽的身份与条件。宁可多几行，也不要合并出语义不明的行。

## 3. 单元格级来源追溯

每个非空单元格都要能回答"这个数从哪来"。至少记录：

- `paper_id`；来源文件（正文 / SI）
- PDF 页码；图号或表号（复合图再记子图标号）
- 表格的 0-based 行/列位置，或正文片段原文引文
- 该值的类型（原文明确值 / 图形估读 / 由公式推导）
- 若为推导：公式与输入来源

要求：**页面上任何一格都能一路点到原始证据**。做不到就不要填。

## 4. 同一篇论文内的去重

1. 去重范围：**同一个 `paper_id`（含其明确关联的 SI）内的正文、SI、图表、表格**。
   绝不跨文献去重或合并。
2. 同一数据在多处出现（正文提到、图中标出、表里列出）→ 去重为一条记录，**保留全部来源**，不是删掉其它出处。
3. 取值优先级：
   - **明确给出的值优先**（表格数值、正文明确数字）；
   - 只有一个来源且是图形估读时，才用估读值，并带上估读标记；
   - 明确值与"同一结果的估读值"冲突时，取明确值，同时保留估读记录作为来源备注。
4. 不同条件 / 不同位点 / 不同材料的数据**不合并**，即使数值巧合相同。
5. 去重只做"同一事实的多次出现"，不做"看起来差不多就算同一个"的判定；拿不准就并列保留并注明。

## 5. 冲突处理（局部，不阻塞全篇）

1. 发现冲突（正文与图不一致、SI 与正文不一致、单位矛盾、材料名不一致等）时：
   - 在**该条记录/该单元格**上标注冲突与双方来源；
   - **不要**让整篇论文停下来，也不要因为一条冲突就不处理其它图表或其它行。
2. 不允许 AI 单方面裁决科研结论：能由证据唯一确定才写确定值；不能唯一确定时保留两个候选或留空，并写明缺什么证据。
3. 冲突是记录属性，不是"全篇闸门"。影响面只算到具体的记录/字段。

## 6. 汇总与分析

1. 分析时**按需筛字段**：要哪几列取哪几列，不要求一行所有字段齐全。
2. **不以"ML 就绪"作为入库门槛**：字段不全、暂时用不上的数据照样入库；
   是否进某个训练集是分析阶段的选择，不是入库的准入条件。
3. 汇总结果必须能回指原始证据；汇总层不得覆盖原始值，衍生列另存。
4. 按提取链路区分新旧，不按日期切分。新流程为 `rebuild_data_rows` / `rebuild_data_values` / `rebuild_value_sources`；旧链路 `dft_results` / `electrochemical_performance` 及其审核衍生记录不再用于分析或导出。新流程开始前后的日期、旧记录是否经过 AI 审核、是否标为 ML_Ready，均不改变其来源类别。
5. 数据库与分析默认只读取新流程中的 DFT 行；实验数据保留在新流程中，须显式选择，不能混入 DFT。旧记录迁入新流程的接口停用，应从原 PDF 重新提取并记录来源。
6. 拟合需满足最少有效配对数且计算/反应上下文兼容。多个上下文组不合并成一条全局拟合线；页面必须显示真实阻止原因，不能把条件不兼容写成数据量不足。

## 7. 不要做的事

- 不猜测、不伪造、不用"看起来合理"的值填空。
- 不把不同条件的数据合并成一行以"让表更好看"。
- 不把估读值当作原文精度传播。
- 不因为一条数据有问题就阻断整篇论文的其余处理。

## 8. 原文数值与分析投影合同

`raw_value`、`precision_digits`、`unit` 和来源逐字保存。`numeric_value` 仅为分析用 binary64 投影；服务器不从它反推原文、不自动填值、换单位或舍入原文。

内部共享精确十进制解析只接受完整匹配的以下写法（可有首尾空白）：

- ASCII 十进制及 `e/E` 指数；数值或指数中的负号可为 ASCII `-` 或 U+2212 `−`，例如 `−2.40`、`7.20E−7`。
- 十次幂 `10^-5` 或 `10⁻⁵`；可带十进制系数和明确乘号 `×` / `·`，例如 `7.2 × 10^7`、`7.2·10⁷`。乘号、`^` 周围可有空白，上标必须全为上标数字及可选上标正负号。指数限 1 至 6 位 ASCII 或上标数字。

不用表达式求值，不接受 `x`、`*`、括号、分数、范围、不等式、近似号或尾随单位；`10−5` 无法区分减法与丢失上标，拒绝为其确认数值投影。以上未支持/歧义文本可按原文保存为明确值或推导值并置 `numeric_value=null`，不得猜成数字；仍须合格来源，推导值仍须每条来源都有推导依据。估读必须为受支持的数值写法，不能以 null 绕过精度限制。

非空投影必须有限，且等于精确十进制值转换的 binary64；不容许非零原值下溢为零。高精度原文独立保留，即使 binary64 无法保留全部有效位。正负零按数值相等处理，符号仍保留在原文。估读最多两位小数，按指数展开后的精确 Decimal 指数判断（含系数末尾零），`precision_digits` 也不得超过 2；例如 `1.20 × 10^-1` 保留三位小数，仍拒绝。估读投影共用 binary64 一致性检查。

相同单位下，数值等价比较共用上述精确解析，不以 float 近似合并不同十进制值；等价表示的原文、精度与来源作为各自候选保留，不覆盖已有原文。不受支持的文本按文本比较。旧库不做批量改写；旧冲突和历史回执不因此自动重算。

`rows/import` 的 HTTP 200 不等于所有格写入：须检查 `complete`、`rows_partial`、`errors`、各格 `persisted/outcome` 并读回。相同 `request_id` 和原请求会重放旧 partial 回执，修复代码不改变历史回执。补齐须先核对当前行/格及原回执，在另行取得科学写入授权后，用新 `request_id`、回执中的 canonical `row_key`、不变的身份/条件/原文/来源，通过正常导入补充被拒格；不得删除或盲重放整批。出现身份待补字段时须按现有恢复协议提供全部 pending dimension 值。

## 2026-10-26 源码候选：正文与SI优先规则

对同篇、同材料/条件/指标、相同原文单位的两个explicit候选，可信已登记正文main优先于SI。角色来自本篇活动文件记录且核对真实原文件hash；客户端label/source_kind不赋予正文身份，未知或退役来源不升级。两个录入顺序都保留SI原值、双方source_ids、原文精度与value_conflict；正文优先只选择当前显示值，不等于独立裁决冲突已解决。不同条件分行，不同单位保留unit_conflict且不转换；不回写或重算历史记录，只作用于此后的正式导入。
