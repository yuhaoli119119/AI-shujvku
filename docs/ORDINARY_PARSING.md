# 普通解析

在 AI 提取页选择当前正文与 SI，点击一次解析。自动逐文件执行读取原文、图表整理和数据提取；允许有依据的估读、缺失与待核实。已有结果保留，文件或字段失败会显示具体原因，可以继续未完成范围。普通解析无需逐格审批或全篇科学独审。

## 恢复与边界

- 每个文件的源 SHA256 和三个阶段持久保存在任务记录中。继续未完成范围只复用源哈希不变的已完成阶段；替换文件使用既有文件生命周期接口。
- 应用重启后恢复器只处理普通解析自身的任务。明确尚未发送的请求可以续发；已经发送的任务只核对其原生 thread/turn 身份，未知执行不自动终止或新建写者。
- 失败任务仅在原生终态被核实后允许重试。同篇存在其他未解决写者时保持保护，其他篇可独立处理；陈旧外部任务缺少身份时须另行受控核实，不能凭时间释放。
- 统一客户端 `scripts/ordinary_parse_client.py` 保存原请求和回执，数据行先预检。同一请求重放不重复写，429/502/503/504 和网络错误最多三次退避重试（一次初始请求加三次重试）；耗尽预算后保留可重放请求和具体错误。
- 上述退避适用于工作台 HTTP 调用。模型提供方自身的推理限流和目标任务续跑由原生运行时控制，应用不会伪称已接管或验证其内部重试。
- DOCX 使用现有 OOXML 来源校验，读取接口返回哈希、段落/表格单元格位置，page=null。文本引用可用不意味着具备物理页面裁图。

任务结束、阶段完成和已存数量均不代表科学 accepted；需要高精度或训练数据时再选择科学精修和独立验收。普通解析不得把原文未报告项补成猜测值。

## 接口与客户端

`POST /api/rebuild/papers/{paper_id}/ai-extract/jobs` 可带 `model`、稳定 `request_id`、当前 `file_ids`、`retry`。同 ID 同参数返回原任务，不同参数返回冲突。

`GET /api/rebuild/papers/{paper_id}/ai-extract/jobs/{job_id}` 返回阶段、断点版本和是否可重试；`PUT .../{job_id}/checkpoints` 在登录会话、来源和 CSRF 校验后保存阶段。请求携带稳定 request_id、file_id、stage、status、expected_revision，失败/partial须reason。

`GET /api/rebuild/papers/{paper_id}/files/{file_id}/reading-text?offset=0&limit=25` 分页读取原始 DOCX；PDF沿用 text-pages/render-page。仅以注册文件自身的哈希和合法定位作为来源。

客户端 `--help` 列出 get/write/checkpoint；仅支持本篇图表与数据幂等导入，登录凭据只在本机读取，不写入请求日志。每篇无需新建临时导入脚本。

目标任务由原生运行时自动启动时，系统从新建空任务和精确目标回执接认原 turn，不再发送第二个启动。历史派发中记录仅在派发日志与实时同一原生线程交叉匹配后恢复身份；大于1MB的原生记录使用有界32MB读取。普通解析六阶段均已处理、原生 idle 且目标明确为空时可记执行结束；目标读取失败与未知身份仍保留待核实。
